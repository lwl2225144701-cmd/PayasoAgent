# scratch/ — 一次性验证脚手架

放**一次性的**验证脚本与临时页面（playwright 探针、临时挂载入口、临时 HTML 等）。

**这个目录里除本文件外全部被 git 忽略**（见根 `.gitignore`）。约定：

- 任何"只为验证一次"的脚本都放这里，或命名为 `*.scratch.*`
- 不要在 `web/`、`tests/` 等真实源码目录里留临时文件
- 用完就删；留下的虽然不进提交，但会干扰后续排查

## 为什么有这个约定

做发送队列那次，临时脚手架放在了 `web/` 下，收尾用 `git add -A` 把 8 个临时
文件一起提交了，靠 `git commit --amend` 才剔除。根因是当时 `web/` 目录没有
`.gitignore`，临时文件全在 git 眼皮底下。

## 顺带一条纪律

**不要用 `git add -A`**：显式列出要提交的路径，或提交前先看 `git status`。
上面的约定只解决"临时文件不该进库"，解决不了"忘了检查"。

## 另一个坑：写入可能静默丢失

本项目所在的环境里遇到过**文件写入"报成功但没落盘"**的间歇性现象
（`write` 工具与 `cat >` heredoc 都中过招，多写操作挤在一条 shell 命令里时更容易
出现）。10 次对照测试无法稳定复现，与仓库本身无关。

**规避办法**：写完关键文件后回读校验（`ls -la` 看 mtime、`grep` 看内容），
不要只凭工具返回的"成功"就往下走。
