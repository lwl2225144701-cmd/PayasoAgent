本方案面向通用 Agent。GitHub 清理任务用于复盘，治理规则适用于代码开发、文件处理、联网调查等场景。实现复用现有工具安全、错误分类、checkpoint 和前端事件机制。

## 二、现有控制缺口与参考边界

### Payaso 当前已具备的控制

现有代码已经包含工具 deadline、确定性错误不自动重试、同参数失败阻断，以及 `non_idempotent` 操作的 executing / succeeded / uncertain 生命周期保护。新增方案应补足覆盖范围和状态语义，保留这些既有保护。[S3]

当前进度提醒累计只读回合，默认要求至少 8 回合和 120 秒；`other` 活动会重置计数。复杂 Shell 命令通常被安全分类为可能产生副作用，因此调查行为可能无法累计。安全效应分类描述的是操作风险，不能据此认定目标取得了进展。[S4]

当前错误回传还存在笼统的"修正参数或换其他方法"指引。对于明确的策略拒绝，这类提示容易诱导换方式重复尝试；普通工具成功返回也可能仅说明进程退出，无法证明命令内部的远端业务操作成功。

### DeepSeek Harness 可借鉴的机制

| 机制 | 可采用的设计 | 适用边界 |
|---|---|---|
| 重复调用提醒 | 参数规范化、分级提醒；拒绝调用同样计数 | 主要覆盖连续同工具同参数；本次记录回放无命中 |
| 超时与失败语义 | 稳定错误码、有界重试；策略拒绝使用专门指引 | 工具超时不能限制模型持续生成；一次升级须存在合法授权通道 |
| Goal 预算与状态 | 准入检查、预算可见；停止原因持久化 | Goal round 是自主续行单元；不能直接作为内层模型迭代数 |
| 终局收尾 | 引用原始目标和已有证据；明确阻塞与后续条件 | wrap-up 本身是提示词；完成声明仍需交付核查 |

### 需要明确保留的限制

DSH 的 blocked 下限在执行点检查 `roundsStarted`；源码没有独立证明"同一阻塞条件连续存在三轮"。Goal 服务也明确声明没有独立 evaluator。重复提醒、计数预算和模型自报完成，均不能替代任务验收。[S5][S6][S7]

DSH 的扩展点分层值得借鉴。Payaso 可沿用现有 Harness 接口，Runtime 仅补完整调用事件与决策执行接线；策略保持独立、可配置和可测试。

## 三、通用调用治理方案

### 完整观察每次调用尝试

新增独立调用观察策略。调用身份采用工具名与深度排序后的 JSON 参数；记录执行、拒绝、失败、回放、结果不确定和参数校验失败等处置。统计放在统一收口处，确保提前 return 的拒绝及回放路径也能被观察。

检测键保存为摘要，提醒仅展示脱敏后的有界参数预览。首版可采用连续重复阈值 3/5/8，提醒附加到下一轮上下文并记录事件。该策略仅提示重复，不取消安全检查，也不据此阻断合法轮询或验证。

同一 checkpoint 恢复时保留观察与预算状态；新的用户指令开启新的观察上下文。界面刷新、重连和工具回放不应清空预算。被明确授权的重试仍须保持原操作身份和审批范围。

### 对不同失败使用不同恢复路径

| 结果类别 | 运行控制的处理 |
|---|---|
| 确定性错误 | 保留具体原因；允许依据新证据修正输入。相同失败原样重放不消耗新的实际执行机会。 |
| 策略或审批拒绝 | 禁止通过改写命令绕过策略。存在既有合法授权通道时，可申请一次受控升级；拒绝后报告阻塞。 |
| 临时网络或限流 | 只有允许重试的操作才进入有上限的退避；工具能提供 `Retry-After` 或恢复时间时，交给 Host 等待。 |
| 结果不确定 | 复用现有 uncertain 保护，先查询实际效果；禁止自动重做可能已产生副作用的操作。 |
| 无法可靠分类 | 保留退出码、stderr 和原始证据，标记不确定；避免凭文本片段认定成功或永久失败。 |

### 覆盖换命令反复调查的情况

不同命令可能在重复调查同一问题，参数摘要不能可靠识别这种语义等价。首版采用周期性目标审查与累计预算覆盖：审查基于全部已完成工具回合，不再依赖安全 effect 是否为 read。

审查提示只携带原始目标、近期工具结果摘要、已知阻塞和剩余预算，要求下一步说明要解决的具体问题。对有稳定错误码且外部条件未变的阻塞，准入判断可直接阻止无依据重试；对任意 Shell 内部业务含义，保持告警与预算兜底。

## 四、执行预算与可信交付

### 在调用前检查预算

预算归 Harness 策略持有。建议提供 `maxModelCalls` / `maxOutputTokens` / `maxActiveMs` 三项配置；工具调用准入和下一次模型调用前均检查。模型持续输出会续期 idle timeout，累计预算则持续消耗，两者分别计量。

先用 70% 消耗触发预警，90% 触发一次收敛审查，耗尽后停止新工具工作。收尾使用预留的小额生成预算；预留不足或模型未正常结束时，由 Host 给出确定的停止说明并保存现场。单轮生成截断不得继续执行不完整工具参数。

预算恢复沿用累计值；增加预算必须来自明确的用户操作或 Host 策略。活跃时间包含模型生成和工具执行，人工审批等待单独计时。实际 usage 缺失时使用明确标注的保守估算，不将估算写成真实消耗。

阈值采用可配置策略。重复阈值 3/5/8 和现有 8 回合 / 120 秒审查条件可作为回放起点；普通与复杂任务的硬预算须在多类样本回放后确定。首阶段可观察不拦截，启用硬限制的配置必须是有限正数。

### 保持原始目标和独立结果语义

将现有 `Run.task` 保留为目标依据。模型可以更新计划，但计划标题或全部 completed 不能替换用户目标。用户后续修改目标时记录关联关系；Agent 自行改写计划不构成目标变更授权。

保留现有 `run.status` 的运行生命周期语义，新增独立的 `deliveryOutcome` 与 `stopReason`。预算停止可映射到 `stopped`；自然完成一次回答仍可为 `completed`，但交付结果可以是 `partial` / `blocked` / `unknown`。页面应分别显示"执行已结束"和"目标是否完成"。

建议停止原因使用稳定 code，例如 `budget_exhausted` / `policy_denied` / `tool_unavailable` / `outcome_uncertain`。新增字段进入 checkpoint 事件和持久化存储；旧记录没有依据时显示 `unknown`，避免推断历史任务已完成。

### 核查测试副作用和最终报告

验证必须区分真实执行、模拟执行、静态检查和未验证。模拟测试在临时仓库或受控 fixture 中运行，网络与进程调用分别注入替身；仅 mock `fetch` 不能声称所有副作用均已隔离。

收尾列出原目标达成情况、实际变更、验证证据、未完成项与外部条件。普通 Git 工作区状态无法显示标签删除，应补相应引用检查。任意 Shell 内部副作用的完整识别仍受执行可观测性限制，不能仅靠提醒宣称已解决。

### 分阶段落地

第一阶段补完整事件、重复提醒与失败语义；对本次历史记录离线回放，并用正常长任务验证误报。预算先进入观察模式，提供可追溯消耗与触发记录。

第二阶段启用可配置机械预算和持久停止原因，落实收尾预留、取消传播、恢复以及前端状态。默认值由多类任务回放决定，灰度观察后扩大使用。

第三阶段补原始目标核对、验证类型标记、临时仓库测试与变更核查。交付状态的机械证据先覆盖文件、Git 引用等明确对象，复杂业务验收保留独立判断。

每阶段分别提供代码差异、确定性测试和行为回放证据。策略开关可关闭新提醒或预算，既有沙箱、副作用保护和 uncertain 语义始终保留。

## 六、验收与发布要求

| 场景 | 验收标准 |
|---|---|
| 连续同工具同参数 | 在配置阈值触发提醒；参数字段顺序不同仍命中；提醒有界且可从事件重建。 |
| 拒绝和结果回放 | 提前返回路径同样计数；重复观察不造成第二次真实副作用。 |
| 换命令调查 | 按全部工具回合触发目标审查；本次 43 次调用可触发预算或审查路径，不伪称精确重复命中。 |
| 策略拒绝 | 恢复指引不诱导绕行；合法升级仅按既有授权范围执行一次；拒绝后保留原因。 |
| 模型持续长输出 | idle 正常续期时累计预算仍有效；超限不会执行截断参数，并能输出停止说明。 |
| 取消与恢复 | 用户取消终止在途调用；重连不重置预算；恢复保留计数和 uncertain，避免重复写入。 |
| 计划改写与目标偏移 | 原始目标仍可追溯；写脚本与完成远端清理分别呈现，计划全勾选不直接证明目标完成。 |
| 模拟验证 | 在临时仓库测试；网络和本地进程均隔离，真实工作区文件及 Git 引用前后保持不变。 |
| 兼容性与正常长任务 | 旧 checkpoint 和事件正常读取；正常多步开发、分批阅读和合法轮询不会被重复提醒硬性否决。 |
