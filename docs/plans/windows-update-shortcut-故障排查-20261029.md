# Windows 更新后快捷方式失效排查（2026-10-29）

> 状态：修复提交为 `772f511`，已授权随 v0.4.22 发布；实际构建及资产状态以 [Release](https://github.com/lwl2225144701-cmd/PayasoAgent/releases/tag/v0.4.22) 为准。v0.4.21 不包含本次修正。Windows 实机跨版本更新仍待验收。
>
> 本文记录“更新成功后快捷方式失效”。此前“安装并重启无反馈”的排查见 [桌面更新安装无反馈排查](desktop-update-故障排查-20261018.md)。

## 现场证据

用户描述的操作顺序为：点击新版本下载 → 安装并重启 → 新程序正常启动且显示正确版本 → 再双击图标时提示快捷方式无法正常工作。

Windows 提示内容为：该快捷方式指向的项目“PayasoAgent.exe”已经更改或移动，询问是否删除快捷方式。

- **用户已确认**：新版本能够正常运行，版本号正确，当前问题集中在快捷方式。
- **尚未取得**：更新前的版本号、报错快捷方式的实际位置与完整目标路径、该机安装和快捷方式修复日志。
- **尚未确认**：报错的是当前用户桌面链接、公共桌面链接、改名后的链接，还是任务栏固定副本；也不能认定链接具体在何时被改写。

## 源码确认

修复前存在以下缺口：

1. 程序调用 `shell.writeShortcutLink()` 后仅依赖布尔返回值，没有读回链接验证目标。
2. 更新后的修复只在启动时和 3 秒后执行；3 秒检查成功即记录当前版本已核验，之后本轮不再复查。
3. NSIS 安装脚本创建链接后直接 `ClearErrors`，没有保留快捷方式写入失败的诊断。
4. 安装器优先通过开始菜单快捷方式启动新程序，存在依赖失效链接的风险。用户本次已能启动新版本，因此这一项是独立加固，不能据此认定为现场根因。

本地 electron-builder NSIS 模板确认：更新卸载阶段会将旧文件移入临时目录，再写回新文件。链接跟踪导致旧目标变化是排查方向；当前缺少该机链接及日志证据，尚未证明它就是本例根因。不能把代码注释中的历史解释当成本次实机复现。

## 本地修复

| 文件 | 改动与目的 |
|---|---|
| `apps/desktop/src/windows-shortcut.ts` | 增加写后读回核验；更新首次检查刷新已有链接；增加有界复查及取消逻辑，末次成功才记录版本。 |
| `apps/desktop/src/main.ts` | 接入新的修复流程，使用当前进程 EXE 构造目标；快捷方式诊断接入更新日志；退出时取消待执行的复查。 |
| `apps/desktop/src/update/coordinator.ts` | 导出已有更新日志函数，供快捷方式修复复用。 |
| `apps/desktop/build/installer.nsh` | 更新后检查 EXE 存在并直接启动 EXE；创建快捷方式失败时尝试写入安装器诊断文件。 |
| `tests/desktop-update.test.ts` | 增加写后核验、延迟失效、失败重试及退出取消的回归场景。 |

程序侧具体行为：

- 带 `--updated` 启动，或当前版本尚未核验时，执行更新后的修复流程；首次刷新已有链接，并允许补建缺失链接。
- 写入后读回目标路径，按现有匹配规则检查工作目录、图标和应用身份；这些可选字段非空时才参与比较。API 返回成功但读回不匹配，仍判定失败。
- 启动后在第 3、10、30 秒复查；最后一次成功才写入版本标记。失败或标记写入失败时，下次启动继续尝试。
- 普通启动仍检查已有链接；本版本已核验后，不补回用户主动删除的图标。更新后的 30 秒窗口内允许补建缺失链接。
- 自动修复范围仍是当前用户桌面、当前用户开始菜单中的 `PayasoAgent.lnk`。公共桌面、改名链接及任务栏固定副本未覆盖。

3/10/30 秒是本次有界重试策略，不是 Windows 对链接跟踪完成时间的保证。

## 日志与重启行为

- 程序日志：`userData/logs/updater.log`，Windows 默认位置为 `%APPDATA%\PayasoAgent\logs\updater.log`。搜索 `[shortcut]`，查看链接位置、写入前目标、读回目标、预期 EXE 和失败信息。日志沿用原有约 1 MiB 轮转规则。
- 安装器诊断：安装目录下的 `shortcut-repair.log`，仅在捕获到快捷方式相关错误且日志可写时记录；没有该文件不能证明安装器未出错。
- 版本标记：`userData/windows-shortcut-version`。只用于判断是否需要执行更新后的补建与复查，不是安装成功证明。
- 若程序在末次复查前退出，不记录本次核验完成，下次启动继续处理；已发布的旧包不会因本地源码修改而自动获得修复。

## 待实机验收

在包含本修复的新安装包发布后，用真实旧版本执行完整“下载 → 安装并重启”流程：

1. 更新前记录旧版本、安装目录、桌面和开始菜单链接的目标，保留日志。
2. 更新重启后确认程序版本正确、工作区可用，再分别从桌面与开始菜单启动。
3. 在更新后约 3、10、30 秒及退出程序后检查链接，确认目标始终指向当前安装目录的 EXE。
4. 检查 `[shortcut]` 日志和版本标记；若仍失败，先区分当前用户链接与公共/固定副本，再决定是否扩大修复范围。
5. 本版本成功核验后主动删除桌面图标，再正常启动程序，确认不会被重新创建。

只有完成上述实机验证，才能认定本次现场问题已解决。构建成功、安装包上传成功或自动化测试通过均不替代这一步。
