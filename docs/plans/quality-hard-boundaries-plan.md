# 质量修复：从提示词改为可验证约束

> 状态（2026-09-20）：连续分页、文件范围约束与来源摘录已实现为 Host API/内部能力。普通 Web 输入不展示独立约束控件，继续使用现有权限菜单。文件范围 12/12、来源校验 11/11、Host 生命周期 5/5 通过；macOS Shell 包含矩阵已实际启动沙箱验证。真实 LLM 评测和 Windows 实机验收待进行。[接口说明](task-constraints-usage.md)

## 决定

停止用不断加长提示词追求“永远不犯错”。工具行为用代码保证，写入范围用权限保证，来源事实用证据保证。模型负责选择与组织，不负责决定自己有没有越界、是否验证通过。

## 三件事

| 问题 | 最小机制 | 放在哪一层 | 能保证什么 |
|---|---|---|---|
| 长文跳过中间内容 | 连续分页、唯一下一页游标，逐页完整性测试 | 文件工具；预算复用共享模块 | 按游标读取不漏行；不能保证模型必然继续读 |
| 只准修改 A 却新增测试文件 | Host 固化允许写入的文件；write/edit 执行前校验；受限任务的 Shell 对工作区只读，缓存仅写已有临时目录 | Host 决定授权；Runtime 传递；工具/沙箱执行 | 已确定的范围不能被模型绕过，包括 Shell 重定向、脚本子进程 |
| 总结补造前提、职责、处理办法 | 来源模式提交“所问项目、文件、版本、起止行”，Host 校验并提取原文，直接渲染证据；不渲染模型自由补写的事实句 | Harness 定义输出；Host 校验/投影；前端显示 | 展示的引文确实来自指定版本；不能保证选中的引文一定完整回答问题 |

### 写入范围的授权来源

这是关键前提，不能略过：自然语言理解本身会错。允许文件必须来自用户明确选择或可信任务参数；模型提出的范围不能自动成为授权，更不能自己扩大范围。自然语言限制需先转成可确认的任务约束，有歧义时执行前问清，不能声称任意一句话都已被权限系统准确理解。

第一版只实现明确文件集合，不做通配符、复杂目录策略或通用自然语言权限解析。未提供范围的普通任务保持现有权限。基线若增加结构化范围参数，必须作为独立验证轨道记录，不能改旧题参数后冒称旧自然语言问题已根治。

受限任务统一让 Shell 工作区只读，可以复用当前 macOS 和 Windows 的只读沙箱及临时目录机制；不必先实现两套逐文件 Shell 写权限。需要落盘的正式修改通过受控 write/edit 完成。无法执行只读隔离的平台拒绝该执行方式，不降级放开权限。

### 来源内容与分析分开

第一版通过输入框显式选择来源摘录模式，不改变所有聊天回复。项目标签来自用户填写，不让模型通过标题夹带新结论。此模式仅展示核验过的原文摘录与来源，暂不提供额外分析。

来源使用工作区内规范化路径、文件版本和行号；路径越界、引用失效、行号错误都不发布为已验证证据。校验失败直接结束，不自动追加模型调用。项目无引用时显示“未找到证据”；缺失所问项目则拒绝结果，不由模型编一个条件补齐。

**自由语言总结无法靠一个裁判模型获得绝对正确保证。** 证据模式消除的是“凭空添加事实也能原样展示”的通道；相关性、完整性和跨句推理仍需要独立评估。再调用一次模型只能降低错误，不能当作硬保证。

## 实施顺序与验收

1. 保留连续分页修复；确定性验证连续、唯一游标、完整遍历、预算上限与超长单行提示。
2. 先做文件范围硬约束：故意让模型/测试直接写范围外文件，并用 Shell、重定向、子进程、软链接绕过。验收看磁盘未被修改，不看模型是否听话。macOS 本机实测；Windows 单独实测后才能宣称支持。
3. 再做来源证据模式：故意提供错误行号、文件越界、旧版本、与原文不符的文本，验证都不能成为已核验引用；保留独立的内容完整性验收。

不增加通用工作流引擎，不在 Runtime 中解析文档或判断文字对错，不用评测关键词拦截真实用户答案。已有 Trace、交付展示和沙箱继续复用。
