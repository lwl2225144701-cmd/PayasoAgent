# Agent 任务交付能力改造计划

> 状态：四项能力已实施，确定性测试及真实 LLM 交付闭环已通过。

## 一、目标

让用户在任务结束后能直接找到结果、看懂完成情况，也能发现执行中的低效行为，并复用常用任务。

例如：选择“文档对比” → 上传两版文档 → Agent 生成差异报告 → 展示报告和检查结果 → 下次继续复用。

## 二、要做的四件事

| 方向 | 要做什么 | 复用现有能力 |
|---|---|---|
| 交付物展示 | 回复末尾列出本次生成、修改的文件，支持查看和下载；文件失效或被后续修改时给出提示 | 已有文件列表、预览和下载能力 |
| 完成依据 | 展示交付文件、实际执行的检查和未完成事项；没有检查记录时明确说明 | 最终回复、工具执行记录、任务状态 |
| 减少无效执行 | 展示疑似重复读取、重复失败、慢调用和 token 消耗，帮助定位问题 | Trace 和现有统计；先做诊断，不自动阻断执行 |
| 复用工作方式 | 完善任务模板的选择、参数提示和发送前预览，提供“文档对比”“项目审查”两个样例 | 现有 `/命令`、Prompt 模板和 Skill |

## 三、实施顺序

### 第一步：让用户找到交付物

完善现有文件展示，覆盖文件工具及 Shell 生成的已知产物。失败或停止的任务，若留下文件，也能查看。

**完成标准：** 用户能找到本轮实际产出的文件并下载；不会把只读过的文件算作产物。

### 第二步：说明完成情况

在交付物旁展示实际检查记录，引导 Agent 说明做了什么、检查了什么、还有什么没完成。

**完成标准：** “运行结束”不会被当作“验证通过”；检查失败、未检查和未完成事项都有明确说明。

### 第三步：看见低效执行

在执行详情中增加重复调用和耗时提示，支持定位对应记录。先观察真实任务，再决定是否增加执行中的提醒。

**完成标准：** 能解释哪里可能低效、依据是什么；正常分页读取和修改后的复查不会被直接阻止。

### 第四步：复用常用任务

完善已有模板入口，补参数提示和展开预览，交付两个可用样例，并跑通一次完整任务。

**完成标准：** 用户不用重复编写长指令，就能发起文档对比或项目审查，最终拿到文件和完成说明。

## 四、代码放在哪一层

- **工具层：** 执行读写和命令，返回实际结果。
- **Runtime：** 执行工具并记录过程，不加入产品展示逻辑。
- **Host：** 汇总交付物、检查记录和执行统计，管理模板入口。
- **Harness：** 引导 Agent 使用工作方法、检查结果并说明缺口。
- **前端：** 展示文件、完成依据、诊断信息和模板操作。

优先复用已有代码，每份数据只保留一套汇总逻辑；不新增工作流引擎、长期记忆系统或模板管理平台。

## 五、如何验收

用三个实际任务贯通检查：

1. **文档对比：** 上传两版文档，生成报告，查看并下载。
2. **代码修改：** 修改文件并执行检查，展示真实检查结果；检查失败时如实说明。
3. **继续修改：** 在下一轮修改已有报告，文件展示能反映变化，模板可以再次使用。

每一步先做相关定向检查，四项完成后跑一次全量确定性测试，再执行上述真实任务验证。

## 六、落地记录

- **入口：** 有文件、检查、未完成计划或诊断问题时才显示对应部分；全部为空时整块隐藏。停止或失败的任务也保留已有产物。
- **模板：** 输入 `/compare-docs` 或 `/review-project`，查看参数提示和展开预览；可先将预览内容放回输入框编辑。
- **职责：** `src/host/run-delivery.ts` 负责汇总，前端只展示；Harness 引导最终回复，Runtime 未加入交付业务。
- **依据边界：** Shell 产物来自最终回复中的文件链接，明确标为 Agent 报告；检查命令为启发式识别，展示实际退出状态，不等同于任务验证通过。
- **文件版本：** 打开、下载均读取当前工作区文件；通过修改时间提示本轮结束后的变化，不保存历史快照。可手动刷新。
- **验证：** 全量确定性测试 92/92；真实 MiniMax-M3 完成文档对比、下载、代码修复检查、项目审查、继续修改并识别旧文件变化。
- **复跑：** `npm run test:delivery` 单独执行真实 LLM 验收，使用临时工作区；不加入确定性测试集合。

验收记录：确定性测试日志为 `.payaso/logs/run-all-2026-09-18T02-07-49-831Z.log`；真实 LLM 及浏览器交互已验证，临时服务已关闭。
